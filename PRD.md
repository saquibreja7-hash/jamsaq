# GemSack Agency Website PRD

## 1. Document Control

**Product:** GemSack Agency marketing website  
**Version:** 1.0  
**Date:** 2026-05-11  
**Owner:** GemSack Agency  
**Primary goal:** Build a modern, premium, conversion-focused web design agency website that positions GemSack as a strategic design and development partner for ambitious businesses.

## 2. Executive Summary

GemSack Agency needs a polished website that can act as a digital storefront, credibility engine, portfolio hub, and lead-generation system. The website should communicate that GemSack is not simply a visual design vendor; it is a web design partner that combines strategy, user experience, brand storytelling, web development, conversion thinking, and long-term digital growth.

The first version should launch as a complete frontend website with placeholder portfolio details and editable content, while being structured for future expansion into real case studies, service landing pages, blog content, client testimonials, and contact automation.

The visual direction should feel premium, editorial, confident, and contemporary. It should avoid generic agency cliches: no bland stock-photo hero, no vague “we build digital experiences” without proof, no overused gradient blob design, and no bloated landing page that hides the real work. It should use strong typography, clean spacing, purposeful motion, sharp service framing, case-study cards, and conversion-oriented calls to action.

## 3. Competitive Research

### 3.2 Competitive Pattern Findings

1. **Strong agency websites lead with a point of view.**  
   Clay leads with “global branding and UX design agency.” Work & Co leads with complex problem solving through design and technology. Fantasy leads with intelligent experiences. GemSack should avoid vague phrasing and state exactly what it does: strategic websites that turn visitors into trust, leads, and revenue.

2. **The best sites frame services as outcomes, not just deliverables.**  
   Ramotion ties design work to brand recognition, user engagement, funding, acquisition, and growth outcomes. Huge frames services around scale and performance. GemSack should describe web design, UX, development, SEO foundations, conversion design, and maintenance through business results.

3. **Case studies carry more trust than decorative design.**  
   Clay, Ramotion, BASIC/DEPT, Baunfire, Instrument, and Huge all bring work forward early. GemSack should include a featured work section even if early case studies are placeholders. Each case card should include problem, solution, services, and measurable placeholder metrics.

4. **Premium agencies use editorial pacing.**  
   Strong sites alternate between large statements, proof blocks, project cards, service sections, and high-contrast calls to action. GemSack should feel like an intentional narrative, not a stack of unrelated sections.

5. **Navigation is usually simple.**  
   Common navigation: Work, Services, Process/About, Insights, Contact. GemSack should start with Home, Services, Work, Process, About, Contact, with anchor-friendly sections on the first version.

6. **Modern agency sites use motion carefully.**  
   Awwwards-style portfolios rely on micro-interactions, hover states, scroll reveals, and subtle kinetic typography. GemSack should include tasteful motion that improves perceived quality but does not harm performance or accessibility.

7. **Trust signals need to appear before the contact ask.**  
   Client logos, recognitions, process, testimonials, case cards, and clear service details should come before the main conversion block. Since GemSack may not yet have real client proof, the first build should use editable placeholders and clearly structured proof areas.

8. **Contact needs to reduce friction.**  
   Work & Co and Huge make contact intent explicit. GemSack should include a short project inquiry form with project type, budget range, timeline, and message, plus direct email and WhatsApp/phone placeholders.

9. **Insights can support authority later.**  
   Baunfire and BASIC/DEPT use insights/news. GemSack should include an “Insights” preview section in the design but can keep it placeholder or hide it until real content is ready.

10. **AI positioning is now common but should be grounded.**  
    Clay, Fantasy, Huge, and Work & Co all reference AI or intelligent experiences. GemSack can mention AI-assisted research, prototyping, content systems, or analytics, but should avoid inflated claims.

## 4. Brand Strategy

### 4.1 Brand Name

The agency brand is **GemSack Agency**.

The spelling should remain consistent across the website:

- Primary: GemSack Agency
- Short form: GemSack
- Avoid: GemSaq, Jamsaq, Gemsac, Gem Sack unless deliberately used as a stylized logo mark later.

### 4.2 Brand Positioning

**Positioning statement:**  
GemSack Agency designs and builds conversion-focused websites for ambitious brands that need clarity, credibility, and growth.

**Alternative hero statement:**  
Websites with strategy, polish, and momentum.

**Supporting message:**  
We blend brand strategy, UX design, Webflow/React-ready frontend systems, and conversion-focused development to create websites that look premium and work hard.

### 4.3 Brand Personality

GemSack should feel:

- Strategic
- Premium
- Clear
- Modern
- Reliable
- Growth-minded
- Sharp but approachable
- Creative without becoming confusing

GemSack should not feel:

- Generic
- Corporate-boring
- Overly playful
- Overdesigned at the cost of clarity
- Like a copied template
- Like a crypto/AI hype landing page

### 4.4 Tone of Voice

Use concise, confident language. Avoid excessive buzzwords.

Preferred language:

- “We design websites that make your business easier to trust.”
- “Strategy first, visuals second, conversion always.”
- “A premium web presence built around clarity and growth.”
- “From discovery to launch, every page has a job.”

Avoid:

- “We are passionate digital ninjas.”
- “Unlock infinite possibilities with innovative solutions.”
- “World-class digital experiences” unless supported by specific proof.

## 5. Target Audience

### 5.1 Primary Audience

Small to mid-sized businesses, founders, consultants, local service brands, agencies, coaches, SaaS startups, and professional service providers who need a better website to build trust and generate leads.

### 5.2 Secondary Audience

Businesses with outdated websites that need redesign, performance improvement, better mobile UX, improved service pages, or clearer conversion paths.

### 5.3 Buyer Profiles

#### Founder / Owner

- Needs a website that makes the business look credible.
- Wants clear pricing or a clear next step.
- Cares about speed, trust, and growth.
- May not know exact technical requirements.

#### Marketing Lead

- Needs landing pages, conversion improvements, analytics, and SEO-friendly structure.
- Cares about content management and speed to publish.
- Wants process clarity.

#### Startup Team

- Needs a polished website for launch, fundraising, waitlist, or product validation.
- Values speed, design quality, and flexible iteration.

#### Local Premium Service Provider

- Needs strong visuals, clear services, testimonials, and lead capture.
- Wants to look better than local competitors.

## 11. Visual Direction

### 11.1 Design Principles

1. Big typography, restrained palette.
2. Clear section hierarchy.
3. Premium but practical.
4. Strong contrast.
5. Reusable cards and grids.
6. No stock-looking imagery in V1.
7. Placeholder visuals should feel intentional, not empty.

### 11.2 Palette

Recommended V1 palette:

- Background: near-black `#080808`
- Surface: deep charcoal `#111111`
- Light surface: off-white `#f4f1eb`
- Primary text: `#f8f6ef`
- Dark text: `#111111`
- Muted text: `#a8a29a`
- Accent: gemstone green `#b8f36b`
- Secondary accent: mineral blue `#80a7ff`
- Border: `rgba(255,255,255,0.12)`

### 11.3 Typography

Use modern web fonts:

- Display: Plus Jakarta Sans or Space Grotesk
- Body: Inter or DM Sans

Type scale:

- Hero: 72-112px desktop, 44-58px mobile
- Section heading: 44-64px desktop, 34-44px mobile
- Card heading: 20-28px
- Body: 16-18px

### 11.4 Layout

Desktop:

- Max width: 1180-1240px
- Generous vertical spacing
- 12-column inspired grid
- Alternating dark and light sections

Mobile:

- Single-column stack
- Sticky CTA available through header
- No horizontal overflow
- Buttons fit text without wrapping awkwardly

### 11.5 Motion

Version 1 motion:

- Subtle hover transforms on cards.
- Scroll reveal using CSS animation or simple intersection observer.
- Marquee/capability strip may move slowly.
- Respect reduced motion preference.

Avoid:

- Heavy animation frameworks
- Large 3D assets
- Motion that blocks content reading

## 12. Content Requirements

### 12.1 Copy System

The site content should be stored in arrays/objects where possible so it is easy to edit.

Content groups:

- Services
- Case studies
- Process steps
- FAQs
- Testimonials
- Insights
- Metrics

### 12.2 Placeholder Policy

All non-final content should be obviously editable but polished.

Use:

- “Placeholder metric”
- “Sample case study”
- “Replace with real client quote”

Do not use fake client names that look real unless explicitly marked as sample.

## 13. Functional Requirements

1. Navigation anchors scroll to correct sections.
2. Mobile menu opens and closes.
3. Contact form captures field state.
4. Contact form displays success message on submit.
5. FAQ items expand/collapse.
6. Buttons have visible hover and focus states.
7. Layout responsive across desktop, tablet, mobile.
8. No backend required.
9. No external image dependency required for V1.
10. Build passes production compilation.

## 14. Non-Functional Requirements

### 14.1 Performance

- Target Lighthouse performance: 90+ after deployment.
- Avoid large images in V1.
- Use CSS shapes and lightweight UI.
- Avoid unnecessary dependencies.

### 14.2 Accessibility

- Semantic HTML landmarks.
- Keyboard navigable menu and FAQ.
- Visible focus states.
- Sufficient color contrast.
- Form labels or accessible labels.
- Respect reduced motion.

### 14.3 SEO

- Descriptive title.
- Meta description.
- Proper H1/H2 hierarchy.
- Service keywords naturally included.
- Local/global positioning copy.
- Open Graph basics in `index.html`.

### 14.4 Maintainability

- Data-driven components.
- Clear CSS variables.
- Avoid hardcoded duplicate content.
- Keep components understandable.
- No unnecessary abstractions.

## 15. Technical Recommendation

### 15.1 Stack

Required for Version 1:

- Next.js App Router
- React
- Tailwind CSS
- lucide-react for icons

Reasoning:

- Strong routing foundation for future multi-page expansion.
- Server Component defaults for performance.
- Tailwind CSS for fast, consistent responsive styling.
- No backend dependency for Version 1.
- Easy deployment path through Vercel or any Next-compatible host.

## 17. Risks

| Risk | Mitigation |
|---|---|
| Website feels generic | Use distinctive GemSack positioning, strong typography, custom CSS visuals |
| No real portfolio yet | Use structured sample case studies and clearly mark them editable |
| Too much animation hurts usability | Keep motion subtle and support reduced motion |
| Visitor does not understand offer | Use clear service cards and process explanation |
| Contact form has no backend | Use frontend success state in V1 and document backend as V2 |
| Content becomes hard to edit | Store core content in arrays/objects |
